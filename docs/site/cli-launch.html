launch

Откройте базу клиентом, Конфигуратором или браузером.

Вывод

Примеры ответов; пути и длительность зависят от запуска.

launch designer 

v8-runner launch designer

запускает клиент или Конфигуратор по строке подключения; --via web ведёт тонкий клиент по веб-адресу, другие клиенты через веб-сервер не ходят (67)

Классы ответов

Классы относятся ко всем вариантам этой команды; условия отдельных ключей указаны в строках. Примеры ниже показывают форму ответа, а не все сочетания настроек.

Причины отказов и различия между ошибкой команды, ошибкой шага и диагностикой запуска — в словаре ответов.

Варианты ответа

Операция завершилась успешно

Фрагмент успешного текстового ответа:

mode: designer
binary: /opt/1cv8/bin/1cv8
pid: 12345

Режим запуска не подходит цели

У отказа по цели может быть структурный следующий шаг error.next.

ERROR: capability unavailable: a standalone server is opened by its web address: use `launch web` with infobase.web.url; a client is not launched against the gate

MCP-клиент запущен, но готовность не подтверждена

Этот класс относится к launch mcp --wait-ready. При отказе готовности раннер завершает управляемый процесс; наличие PID в результате не обещает работающий клиент.

pid: 12345
MCP endpoint did not become ready
ERROR: runtime error: MCP endpoint did not become ready

launch web

v8-runner launch web

открывает опубликованную базу в браузере

Для отладки выполните web publish --prepare-debug <IDE_URL>, подключите отладчик IDE и включите приём WEBClient. Затем запустите launch web --web-debug <DEBUGGER_URL> с data.debug.debugger_url из подготовки. Раннер добавляет Debug=http,attach и DebuggerURL в адрес веб-клиента.

Варианты ответа

Операция завершилась успешно

Фрагмент успешного текстового ответа:

mode: web
url: https://web.example/demo

launch thin --debug

v8-runner launch thin --debug http://127.0.0.1:12961

запускает клиент предприятия (thin, thick, ordinary, mcp) подключённым к серверу отладки: раннер добавляет клиенту ключи /DEBUG -http -attach /DEBUGGERURL <url> перед ключами --raw-key, и отладчик сам подключает предметы отладки клиента (112). Адрес — тот, что ответил debug-server start: http://<хост>:<порт>, без пути, параметров и учётных данных. Перед запуском раннер сервер не проверяет: если сервера уже нет, клиент работает без отладки. Ответ называет адрес в debug.url. Конфигуратор отлаживается своим отладчиком, веб-клиент ключей запуска не получает: с ними --debug — отказ. Порядок работы — на странице debug-server.

Варианты ответа

Клиент запущен под отладкой

Фрагмент успешного текстового ответа:

mode: thin
binary: /opt/1cv8/bin/1cv8c
pid: 12345
debug: http://127.0.0.1:12961

План запуска под отладкой

С --dry-run клиент не запускается; ключи отладки видны в plan.args. Фрагмент текстового ответа:

mode: thin
binary: /opt/1cv8/bin/1cv8c
debug: http://127.0.0.1:12961
provider dispatched: false
planned program: /opt/1cv8/bin/1cv8c
planned args: ENTERPRISE /IBConnectionString File=/home/user/ib /DEBUG -http -attach /DEBUGGERURL http://127.0.0.1:12961

Отладка не подходит запуску

Отказ до запуска: invalid_argument, выход CLI 2. Так же отвечают launch web --debug, адрес не вида http://<хост>:<порт> (путь, параметры, фрагмент, учётные данные, нет порта или порт 0) и /DEBUG или /DEBUGGERURL в --raw-key или в tools.enterprise.additional-launch-keys рядом с --debug. Отказ не повторяет введённый адрес.

ERROR: validation error: --debug is for the 1C:Enterprise client: Designer debugs with its own debugger

launch thin --interactive-login

v8-runner launch thin --interactive-login

Оставляет выбор пользователя платформе 1С на один запуск. Раннер берёт выбранную ИБ и платформу из проекта, опускает сохранённые имя и пароль и отключает автоматический вход через учётную запись ОС внутри ИБ. Показ окна входа зависит от настроек и сохранённых токенов платформы. Профиль и реквизиты пакетных команд сохраняются.

Ключ работает с thin, thick и ordinary без --wait-for-exit. Для отладки добавьте --debug <url>. Реквизиты в адресе ИБ и сырые ключи, меняющие вход, адрес или платформу, приводят к invalid_argument до запуска. --dry-run показывает план с теми же параметрами входа.

launch designer --dry-run 

v8-runner launch designer --dry-run

Превью проверяет настройки и доступность исполнителя. Платформа не запускается; база и выходные файлы не меняются. Без --dry-run выполняется указанная операция.

Варианты ответа

План запуска подготовлен

Успех превью подтверждает подготовку плана, а не выполнение операции. Фрагмент текстового ответа:

mode: designer
binary: /opt/1cv8/bin/1cv8
provider dispatched: false

Команды, работающие с выбранной базой, принимают --infobase <имя или строка>; без ключа берётся origin. В целевой модели План позиционные аргументы остаются за наборами исходников: push my-ext не должен гадать, ссылка это или база.

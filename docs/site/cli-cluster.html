cluster

Команды cluster запускают и останавливают сервер 1С — ragent, rmngr и rphost — на машине раннера Windows или Linux для базы, объявленной кластером под управлением раннера. Кластер службы или вашей консоли раннер только использует и не трогает его процессы.

Вывод

cluster start План

v8-runner cluster start

Запускает сервер 1С как приложение той же платформы, что выбирают остальные команды (tools.platform). Каталог данных кластера лежит под workPath; порты агента, менеджера и диапазон рабочих процессов раннер выбирает свободными и отдаёт ответ после того, как агент принял соединение. Кластер живёт между командами, пока его не остановит cluster stop. Запись о процессе и портах раннер держит под workPath. На macOS серверных компонентов нет: команда отказывает.

Если кластер уже запущен раннером этой копии, команда ничего не запускает и называет его. Порты, занятые чужим сервером 1С, раннер не берёт.

v8-runner cluster start --dry-run

Показывает исполняемый файл, каталог данных и выбранные порты. Ничего не запускает.

cluster status План

v8-runner cluster status

Отвечает, запущен ли кластер этой копии: не запущен или запущен раннером. Для своего кластера называет PID агента, версию платформы, адрес Srvr= и прошла ли проба готовности. Платформу команда не запускает.

cluster stop План

v8-runner cluster stop

Останавливает кластер, который запустил раннер этой копии, вместе с его рабочими процессами и ждёт их завершения. Данные базы в СУБД остаются. Кластер службы или консоли не останавливает. Если кластер не запущен, останавливать нечего, и команда успешна.

cluster restart План

v8-runner cluster restart

То же, что cluster stop и затем cluster start, для своего кластера.

cluster

Команды cluster запускают и останавливают сервер 1С — ragent, rmngr и rphost — на машине раннера Windows для базы, объявленной кластером под управлением раннера. Кластер службы или вашей консоли раннер только использует и не трогает его процессы.

Вывод

cluster start

v8-runner cluster start

Запускает сервер 1С как приложение той же платформы, что выбирают остальные команды (tools.platform): агент ragent с реестром под localPath, затем сервер администрирования ras, и отдаёт ответ после того, как rac cluster list назвал кластер. Порт агента, regport и диапазон рабочих процессов раннер выбирает свободными вне динамического диапазона и закрепляет при первом запуске: реестр кластера хранит их все. Порт ras выбирается заново при каждом запуске. При dbms.managed команда первым шагом поднимает PostgreSQL, если он не работает. Кластер живёт между командами, пока его не остановит cluster stop. Запись о процессах и портах раннер держит под localPath: удаление workPath кластер не трогает. На Linux и macOS команда отказывает.

Если кластер уже запущен раннером этой копии, команда ничего не запускает и называет его; упавший ras поднимает заново. Остатки своего упавшего агента — rmngr и rphost — снимает по их PID и запускает кластер на прежних портах. Если закреплённый порт занят чужим процессом, команда отказывает, называет его и предлагает --new-regport; другой порт сама не берёт. Пока работает свой автономный сервер этой базы, команда отказывает и называет standalone stop: одну БД держит один сервер.

v8-runner cluster start --dry-run

Показывает состояние, закреплённые адреса и каталог реестра, если кластер уже запускался. Ничего не запускает. Такое же превью есть у cluster stop и cluster restart. Команды cluster принимают только объявленную базу: строка соединения в --infobase — отказ.

v8-runner cluster start --new-regport

Когда закреплённые порты заняты чужим процессом: заводит новый реестр на свободных портах и регистрирует объявленную базу над прежней БД без её создания. UUID базы меняется, данные, поколение конфигурации и память раннера остаются. Если базы ещё не было, остаётся только новый реестр. Прежний реестр удаляется после регистрации и пробы базы, поэтому отказ на любом шаге ничего не теряет. При свободных портах ключ — отказ. Если на прежних портах работает чужой ragent над реестром этой копии, команда отказывает без нового реестра: такой реестр живой.

cluster status

v8-runner cluster status

Отвечает, запущен ли кластер этой копии: не запущен, запущен раннером или его порт занят не раннером. Для своего кластера называет PID агента и ras, версию платформы, адрес Srvr=, адреса агента и ras и ответил ли rac cluster list. Говорит, создана ли база в реестре. Называет и остатки упавшего агента, не трогая их. Клиент и Конфигуратор команда не запускает, замок рабочей копии ей не нужен, ключа --dry-run у неё нет.

cluster stop

v8-runner cluster stop

Останавливает кластер, который запустил раннер этой копии: сначала ras, он переживает агента, затем ragent с его рабочими процессами, и ждёт их завершения; снимает и остатки упавшего агента. Аварийные дампы, которые процессы платформы пишут при такой остановке, удаляет. Данные базы в СУБД и реестр остаются. PostgreSQL, поднятый шагом cluster start, гасит следом, а поднятый dbms start не трогает (таблица владения). Кластер службы или консоли не останавливает. Если кластера нет и гасить нечего, команда успешна.

cluster restart

v8-runner cluster restart

То же, что cluster stop и затем cluster start, для своего кластера. PostgreSQL не трогает.

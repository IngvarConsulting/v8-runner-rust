standalone

Команды standalone поднимают и останавливают автономный сервер ibsrv на машине раннера для базы, объявленной сервером под управлением раннера. К чужому ibsrv раннер только подключается и не трогает его процесс.

Вывод

standalone start

v8-runner standalone start

Поднимает ibsrv той же платформы, что выбирают остальные команды (tools.platform), над файловой базой из standalone.managed.db-path или над базой из секции dbms; база должна быть создана заранее. При dbms.managed команда первым шагом поднимает PostgreSQL, если он не работает. Пароль СУБД ibsrv получает ключом -W через stdin, в командной строке его нет. На Linux и macOS команда отказывает. Раннер сам выбирает свободные порты прямого шлюза, SSH-шлюза и HTTP, создаёт одноразовый ключ хоста для SSH-шлюза и отдаёт ответ только после того, как прямой шлюз принял соединение: готовность проверяется пробой, а не паузой (61, 65). Сервер живёт между командами, пока его не остановит standalone stop. Запись о том, какой процесс поднят, какими портами и с каким ключом, раннер держит под localPath.

Если сервер этой базы уже поднят раннером этой копии, команда ничего не запускает и называет его. Если базу держит чужой процесс ibsrv, команда отказывает и называет его: второй сервер над той же базой не поднимается.

v8-runner standalone start --dry-run

Показывает каталог данных, журнал и закреплённые адреса, если сервер уже запускался. Ничего не запускает. Такое же превью есть у standalone stop и standalone restart. Команды standalone принимают только объявленную базу: строка соединения в --infobase — отказ.

standalone status

v8-runner standalone status

Отвечает, поднят ли сервер этой базы и кем: не поднят, поднят раннером этой копии или поднят не раннером. Для своего сервера называет PID, адреса прямого шлюза, SSH-шлюза и HTTP и отвечает ли прямой шлюз. Чужой сервер только называет: чей он, раннер не знает. Платформу команда не запускает, замок рабочей копии ей не нужен, ключа --dry-run у неё нет.

standalone stop

v8-runner standalone stop

Останавливает сервер, который поднял раннер этой копии, и ждёт завершения его процесса. PostgreSQL, поднятый шагом standalone start, гасит следом, а поднятый dbms start не трогает (таблица владения). Сервер, поднятый не раннером, не останавливает: ответ называет его и говорит, что он не наш. Если сервера нет и гасить нечего, команда успешна.

standalone restart

v8-runner standalone restart

То же, что standalone stop и затем standalone start, для своего сервера. Чужой сервер не перезапускает, PostgreSQL не трогает.

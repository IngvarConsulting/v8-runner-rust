Что такое информационная база

Три конфигурации внутри одной базы и одно число, по которому видно, менялась ли она.

№Платформа утверждаетЧто из этого следуетГде написано
1В информационной базе хранятся минимум две конфигурации: основная, которую правят, и конфигурация базы данных, с которой работают пользователи. Рядом лежат сама база данных и служебные сведения.У раннера две точки назначения внутри одной базы: отправить в основную конфигурацию и привести к ней базу данных.РР 1.4.1
2Объекты конфигурации базы данных доступны только для чтения. Все правки идут в основную конфигурацию.Отправка исходников всегда адресована основной конфигурации.РР 2.14.1
3Приведение базы данных к основной конфигурации — отдельная операция «обновление конфигурации базы данных». Ей нужен монопольный доступ к базе.Отправка и применение разведены. Применение можно отложить до окна обслуживания.РР 2.14.2
4Если монопольный доступ занят, у Конфигуратора три исхода: ошибка блокировки, завершение сеансов с повтором, динамическое обновление. В пакетном режиме поведение при занятых сеансах задаёт ключ -SessionTerminate, по умолчанию сеансы не трогают.Исход применения — часть ответа. Сбоем он не считается. Разрешение завершать чужие сеансы даёт вызывающий.РР 2.14.2.2 РА 7.4.4 /UpdateDBCfg
5После динамического обновления работающие сеансы остаются на прежней конфигурации до перезапуска.«Обновлено динамически» — отдельное состояние базы, которое надо показывать.РР 2.14.2.2.3
6Изменения основной конфигурации можно отбросить, вернувшись к конфигурации базы данных.У базы есть своё непринятое. Его можно потерять, и его можно откатить.РР 2.14.6 РА 7.4.4 /RollbackCfg РА ibcmd config reset
7Сравнение конфигураций различает источники: основная конфигурация, конфигурация базы данных, конфигурация поставщика, конфигурация расширения, конфигурация расширения из базы данных и файл .cf или .cfe.У каждого расширения своя пара «основная ↔ база данных», такая же, как у конфигурации.РА 7.4.4 /CompareCfg РР 2.14.5
8Если конфигурация стоит на поддержке, в базе всегда хранится и конфигурация поставщика.Третья конфигурация в базе существует только для чтения и сравнения.РР 2.5
9В сравнении конфигурация поставщика указывается по имени: параметр -FirstName для типа VendorConfiguration.Конфигураций поставщика у базы бывает несколько, и ссылка на поставщика всегда именована.РА 7.4.4 /CompareCfg
10Загрузка конфигурации из файла .cf полностью заменяет текущую конфигурацию. Конфигуратор предупреждает: изменённая конфигурация будет потеряна.Загрузка пакета уничтожает непринятое в основной конфигурации.РР 2.6 РР 36.15
11Основную конфигурацию и конфигурацию базы данных можно сохранить в файл .cf или .cfe, расширение — по имени.Пакет можно получить прямо из базы, без исходников.РР 2.5 РР 2.14.4 РА 7.4.4 /DumpCfg, /DumpDBCfg РА ibcmd config save
12Идентификатор поколения меняется при любом изменении конфигурации. Сравнивать его можно только на «равно / не равно». У пустой базы он состоит из сорока нулей. Конфигуратору для ответа нужен ключ /Out.Вопрос «менялась ли база» стоит секунду и не требует выгрузки. Сорок нулей означают пустую базу и памятью о базе не становятся.РА 7.4.4 /GetConfigGenerationID РА ibcmd generation-id
13«Сохранение в файл идентификатора конфигурации» — служебная команда механизма лицензирования.Это не поколение. Имена похожи, предметы разные.РР 2.24

Выгрузка и загрузка в файлы

Как конфигурация становится каталогом XML и что при этом помнит платформа.

№Платформа утверждаетЧто из этого следуетГде написано
14Все объекты конфигурации выгружаются в XML-файлы, главный из них — Configuration.xml. Форматов два: иерархический и линейный. Из Конфигуратора доступен только иерархический, линейный устарел.Исходники раннера — иерархическая выгрузка.РР 2.17.1 РР 2.17.4
15Вместе с выгрузкой платформа пишет файл версий ConfigDumpInfo.xml: полное имя объекта, его внутренний идентификатор и «версию». Значения id и configVersion документация называет магическими числами, не предназначенными для внешнего использования.Файл версий читает только платформа. Раннер его не разбирает и не вычисляет.РА Прил. 3, 3.18
16Повторная выгрузка в тот же каталог выгружает только объекты, у которых изменилась версия. Если файла версий в каталоге нет, выполняется полная выгрузка.Работа по изменившемуся держится на файле версий, лежащем в каталоге исходников.РР 2.17.4
17Полная выгрузка выполняется принудительно при переименовании конфигурации, переименовании или удалении объекта, изменении предопределённых данных или диаграммы бизнес-процесса.Быстрая выгрузка может стать полной без предупреждения, и это штатное поведение.РР 2.17.4
18В пакетном режиме ключ -update требует файл версий и совпадение версии формата, иначе ошибка. Ключ -force переводит в полную выгрузку только при несовпадении версии формата.Отсутствие файла версий — отказ, который ключом не лечится.РА 7.4.4 /DumpConfigToFiles
19Ключ -getChanges перечисляет изменения конфигурации относительно файла версий. Ключ -configDumpInfoForChanges берёт файл версий со стороны, но требует пустого каталога выгрузки.Платформа умеет назвать, что изменилось, но не в рабочий каталог.РА 7.4.4 /DumpConfigToFiles
20Ключ -configDumpInfoOnly формирует только файл версий.Файл версий можно получить отдельно, но он опишет базу такой, какая она сейчас.РА 7.4.4 /DumpConfigToFiles
21Версия формата привязана к версии платформы: 8.3.27 пишет 2.20. Выгрузка всегда идёт в формате своей платформы. Загрузка возможна только из формата не новее платформы.Версия формата — дешёвый признак совместимости, который виден до запуска платформы.РР 2.17.2
22Полная загрузка полностью заменяет основную конфигурацию. Для конфигурации под хранилищем полная загрузка недоступна, на поддержке — только при включённой возможности изменений.Полная отправка в базу под хранилищем или на полной поддержке невозможна по устройству платформы.РР 2.17.5.2
23Частичная загрузка возможна только через /LoadConfigFromFiles. Объекты сопоставляются по полному имени и идентификатору. При ошибке платформа возвращается к последней сохранённой основной конфигурации, несохранённое теряется. С несколькими расширениями частичная загрузка не поддерживается.Частичная отправка — только пакетный режим, и при ошибке она стирает непринятое.РР 2.17.5.3
24При загрузке из XML платформа не проверяет корректность настроек поддержки.Загрузка не защищает от порчи поддержки. Ответственность на вызывающем.РР 2.17.5.1
25Ключ -updateConfigDumpInfo после загрузки создаёт или обновляет файл версий в каталоге.Загрузка тоже пишет в каталог исходников.РА 7.4.4 /LoadConfigFromFiles
26Выгрузку и загрузку можно вести через zip-архив с той же структурой. Выгрузку можно выполнять на сервере несколькими фоновыми заданиями.Обмен с удалённой базой может идти одним файлом.РР 2.17.4 РА 7.4.4
27Отдельный механизм выгружает и загружает файлы свойств: модули, макеты, справку, права.Это не исходники конфигурации. Форматом раннера они не являются.РР 2.16
28Утилита ibcmd работает только с иерархическим форматом. Команда export --sync обновляет выгрузку, если совпали идентификатор корневого объекта и версия формата. Команда export status показывает расхождение базы и каталога. Команда export info формирует файл версий. Ключ --base задаёт файл версий со стороны.У ibcmd есть то, чего нет у Конфигуратора: статус без выгрузки и файл версий со стороны.РА 4.10.4.7.8 РА 7.4.13
29Команда ibcmd import с ключом --out записывает импортируемую конфигурацию, внешнюю обработку или отчёт в файл; для внешних обработок и отчётов ключ обязателен. Команда export с ключом --file читает .cf, .cfe, .epf и .erf.Исходники собираются в пакет и разбираются из пакета без информационной базы.РА 4.10.4.7.9 РА 4.10.4.7.8
30Режим ibcmd config полностью эквивалентен режиму ibcmd infobase config по списку команд и параметрам.Команды режима config — тот же набор, что и у базы.РА 4.10.5

Расширения

Расширение — отдельный предмет со своими исходниками, своим именем в базе и своей парой конфигураций.

№Платформа утверждаетЧто из этого следуетГде написано
31Расширение — набор объектов метаданных, подключаемых к основной (расширяемой) конфигурации. Объекты бывают заимствованные и собственные.Расширение — отдельный набор исходников.РР 30.1.1
32Объекты сопоставляются по имени. Переименование объекта в основной конфигурации делает подключение расширения невозможным.Имя объекта — контракт между конфигурацией и расширением.РР 30.1.2
33У расширения есть назначение: исправление, адаптация или дополнение. Подключаются расширения в этом порядке.Назначение задаётся при создании и в исходниках расширения не лежит.РР 30.1.2 РР 30.7.1
34При создании задаются имя, синоним и префикс имён; префикс добавляется к новым объектам. В ibcmd это --name, --name-prefix и --purpose.Чтобы завести расширение, раннеру нужны три сведения помимо исходников.РР 30.2.1.2 РА ibcmd extension create
35Имена расширений и всех их объектов уникальны в результирующей конфигурации. Одно расширение подключается в базе в одном экземпляре.Имя расширения в базе — идентификатор ссылки.РР 30.1.3
36Расширение сохраняется в файл .cfe и этим файлом подключается к базе.Пакет расширения — .cfe.РР 30.2.1.3
37Команды /LoadCfg и /LoadConfigFromFiles с ключом -Extension создают отсутствующее расширение с указанным именем.Первая отправка заводит расширение сама.РА 7.4.4
38Загрузка расширения в основную конфигурацию и основной конфигурации в расширение не поддерживается. Сравнение и объединение их между собой — тоже.Ссылки не смешиваются.РА 7.4.4 РР 36.1
39У расширения своя конфигурация базы данных: /UpdateDBCfg, /RollbackCfg и /DumpDBCfg принимают -Extension.Применение делается для каждой ссылки отдельно.РА 7.4.4
40Расширение, расширяющее данные, удаляется в два шага: отключить, затем удалить. Таблицы его данных удаляются вместе с ним.Удаление ссылки уносит данные.РР 30.2.3 РР 30.7.1
41Обновление расширения не меняет его в уже открытых сеансах.Состояние «до перезапуска сеансов» есть и у расширений.РР 30.7.1
42Свойства установленного расширения меняются отдельно: активность, безопасный режим, защита от опасных действий, область действия, профиль безопасности.Это свойства экземпляра в базе. В исходниках их нет.РА ibcmd extension update
43С ключом -Extension пакетный режим возвращает 0 при успехе и 1 иначе. Одновременно -Extension и -AllExtensions указывать нельзя.У команд с расширением код возврата беднее обычного.РА 7.4.1
44Команда /DumpDBCfgList выводит имя основной конфигурации, имя указанного расширения или имена всех расширений.Имена расширений Конфигуратор перечислит и в пакетном режиме. Их свойства читают и меняют только ibcmd и агент.РА 7.4.4 /DumpDBCfgList

Поставка, поддержка, хранилище

Что ограничивает загрузку в базу помимо самих исходников.

№Платформа утверждаетЧто из этого следуетГде написано
45Поставка — файл .cf особого вида, обновление — файл .cfu. Поддержка — способность конфигурации обновляться такими файлами средствами Конфигуратора.Пакет поставщика применяется своим путём, отдельно от отправки исходников.РР 38.1
46На полной поддержке объекты нельзя редактировать, обновление автоматическое. Включение возможности изменения лишает автоматического обновления.Режим поддержки решает, что вообще можно загрузить в базу.РР 38.3.3.1 РР 38.3.3.2
47Команда /MergeCfg объединяет конфигурацию с файлом по файлу настроек, с ключами -EnableSupport и -DisableSupport. Команда /UpdateCfg обновляет конфигурацию поставщика.«Объединение» у платформы — операция по правилам из файла. Слияния версий в ней нет.РА 7.4.4 /MergeCfg РА 7.4.6
48Хранилище конфигурации — групповая разработка с захватом объектов. Выгрузку в файлы хранилище не ограничивает. Полная загрузка для конфигурации под хранилищем недоступна, частичная возможна для захваченных объектов; у расширения под хранилищем то же.С базой под хранилищем раннер работает: выгрузка без ограничений, отправка только частичная по захваченным объектам. Так устроены gitsync и GitConverter.РР 37.1 РР 2.17.5.2 РР 2.17.5.3 РА 7.4.4 /LoadConfigFromFiles

Варианты работы и компоненты

Из чего состоит система и как к ней обращаются.

№Платформа утверждаетЧто из этого следуетГде написано
49Компоненты системы: информационная база, клиентское приложение, сервер (кластер серверов), СУБД, веб-сервер.Ровно с этими компонентами и разговаривает раннер.РР 1.4.1
50В файловом варианте конфигурация, данные и служебная информация лежат в одном файле 1Cv8.1CD. В клиент-серверном клиент обращается к кластеру, кластер — к СУБД, и клиент не знает, где лежат данные.Базу адресуют двумя способами: путём к каталогу или адресом кластера с именем базы.РР 1.4.2.2 РР 1.4.2.3
51Кластер состоит из рабочих серверов. На каждом работают агент ragent, менеджер rmngr и рабочие процессы rphost. Реестр кластера ведёт главный менеджер.У кластера свои процессы, которыми раннер не управляет.КС 2.2.1
52Кластер администрируется сервером ras и утилитой rac по порту 1545. Версии кластера и ras должны совпадать.Администрирование кластера — отдельный канал, вне обмена конфигурацией.КС 5.3.3 РА 4.13
53Автономный сервер ibsrv обслуживает одну базу, содержит встроенный веб-сервер и администрируется утилитой ibcmd. Его нельзя применять к базе, которой управляет кластер. Сервер ras им не управляет, фоновой реструктуризации нет, линейный формат он не загружает.Третий вид цели со своим набором ограничений.РА 7.1 РА 7.2
54У автономного сервера есть SSH-шлюз, работающий как Конфигуратор в режиме агента, с урезанным набором команд. Из группы config: dump-cfg, dump-config-to-files, load-cfg, load-config-from-files, update-db-cfg, generation-id, extensions, manage-cfg-support, sign-cfg и команды мобильных приложений. Из infobase-tools: dump-ib, restore-ib, erase-data, debug-info. Сравнения, проверок, отката и сохранения конфигурации базы данных в наборе нет. Утилите ibcmd по SSH недоступны создание базы и восстановление её целостности.Для автономного сервера раннеру достаточно SSH. Платформа на его машине не нужна.РА 7.3.5.1.4
55Шлюзы автономного сервера включаются и выключаются: прямой (TCP), HTTP и SSH. По умолчанию все включены.«Шлюз не отвечает» — состояние настройки сервера. Сеть здесь ни при чём.РА 7.3.5.2
56Кластер по умолчанию слушает порт 1541 с диапазоном рабочих процессов 1560–1591. Агент кластера отвечает на 1540, сервер администрирования — на 1545.Адрес кластера в строке соединения — это порт менеджера, по умолчанию 1541.КС 4.2.1 РА 4.13
57У автономного сервера основной порт 8314, порт SSH 1543, ключ хоста по умолчанию ~/.ssh/id_rsa.Клиентский адрес и SSH-шлюз автономного сервера — два разных порта одного процесса.РА 4.9
58Клиентские приложения: тонкий клиент, веб-клиент, мобильный клиент, толстый клиент.Запуск и тесты идут через тонкого или толстого клиента. Веб-клиент открывается браузером.РР 1.4.4
59Строка соединения: File= для файловой базы, Srvr= и Ref= для кластера, ws= для опубликованной базы.Административный адрес и адрес для клиента — разные строки.РА 7.7 РА 7.3.1

Оба файла используют YAML: вложенность задаётся пробелами. Названия ключей чувствительны к регистру. Строки соединения удобно заключать в кавычки.

Как раннер находит файл

По умолчанию читает v8project.yaml в текущем каталоге. В родительских каталогах не ищет. Другой путь задаётся через --config или переменную окружения V8TR_CONFIG; явный ключ имеет приоритет.

v8-runner --config path/to/v8project.yaml push

Локальный файл ищется рядом с выбранным основным файлом, всегда под именем v8project.local.yaml.

Относительные пути исходников и рабочего каталога считаются от каталога основного файла.

Минимальный проект с конфигурацией

workPath: .build         # журналы, временные файлы и состояние раннера
format: DESIGNER         # формат исходников: DESIGNER или EDT
source-set:              # наборы исходников проекта
  - name: main           # локальное имя для навигации и адресации в Unica
    # type: CONFIGURATION, EXTENSION,
    #       EXTERNAL_DATA_PROCESSORS или EXTERNAL_REPORTS
    type: CONFIGURATION  # основная конфигурация
    path: src/cf         # каталог относительно v8project.yaml

В src/cf должны лежать исходники конфигурации. Файл можно создать командой init.

Наборы исходников

workPath: .build
format: DESIGNER
source-set:
  - name: main
    type: CONFIGURATION             # основная конфигурация
    path: src/cf
  - name: my-ext                    # локальное имя набора для навигации
    type: EXTENSION                 # расширение конфигурации
    path: src/ext
  - name: tools
    type: EXTERNAL_DATA_PROCESSORS  # внешние обработки
    path: src/epf

Состав и виды исходников подробнее описаны на странице Исходники.

Информационные базы

infobases в v8project.local.yaml задаёт адреса баз для этой машины. Каждая база имеет локальное имя. Имя origin используется, если команда не получила другой выбор.

# v8project.local.yaml
infobases:                        # базы этой машины
  origin:                         # база по умолчанию
    connection: "File=.build/ib"  # каталог файловой базы

Адрес записывает init: например, File=.build/ib или значение --infobase. infobase create создаёт базу по этому адресу. Команды обмена используют тот же адрес.

Несколько баз и параметры подключения

Добавьте базы под другими именами. Для файловой базы задаётся File, для серверной — Srvr и Ref. standalone задаёт подключение к автономному серверу.

Для кластерной базы учётные данные разделены на три уровня: user/password — пользователь информационной базы; cluster.user/password — администратор кластера; cluster.agent.user/password — администратор центрального сервера. У центрального сервера и кластера отдельные списки администраторов (документация платформы).

# v8project.local.yaml — не коммитится
workPath: .build
infobases:                             # базы проекта, как remote у репозитория
  origin:                              # умолчание, как у гита
    connection: "File=.build/ib"
  test:
    connection: "Srvr=srv;Ref=erp_test"
  prod:
    connection: "Srvr=srv;Ref=erp"
    user: deploy                       # пользователь информационной базы
    cluster:                           # для sessions и создания базы в кластере
      ras: "srv:1545"                  # уже поднятый; без ключа раннер поднимет ras сам
      user: clusteradmin               # имя администратора кластера
      password: "cluster-password"     # пароль администратора кластера
      agent:                           # центральный сервер
        user: "serveradmin"            # имя администратора центрального сервера
        password: "server-password"    # пароль администратора центрального сервера
  ci:
    connection: "Srvr=ibsrv;Ref=demo"  # прямой шлюз автономного сервера
    standalone:                        # объявляет вид цели
      gate: "ibsrv:1543"               # SSH-шлюз: агентский набор без платформы у раннера
      exchange: sftp

Команда принимает --infobase с именем базы или строкой соединения целиком. Строка в ключе позволяет передать адрес из задания сборки без правки файла. Если origin не объявлен, команда требует выбрать базу: init --infobase … или --infobase <имя>.

v8-runner push                                   # в origin
v8-runner push --infobase test                   # в именованную базу
v8-runner apply --infobase prod --sessions force
v8-runner pull --infobase "Srvr=ci;Ref=job-417"  # адрес без правки файла
v8-runner status --all                           # все объявленные базы

HTTP-адрес базы

У базы два адреса: connection нужен для операций с базой, web.url — для открытия опубликованной базы в браузере или тонком клиенте.

# Фрагмент v8project.local.yaml
infobases:
  origin:
    connection: "Srvr=srv;Ref=demo"  # подключение к кластерной базе
    web:
      url: https://srv.example/demo  # адрес веб-публикации
v8-runner launch web             # открыть в браузере
v8-runner launch thin --via web  # открыть тонким клиентом по веб-адресу

web.url задаётся отдельно от connection; его нельзя подставлять вместо строки соединения. Для файловой и кластерной базы нужна веб-публикация. У автономного сервера адрес задаётся по настройкам его встроенного веб-сервера.

Две публикации одной базы — например, demo и demo_int — показаны в примере именованных веб-публикаций План. Именованные публикации объявляются внутри одной базы в web.publications.

Параметры публикации

Чтобы раннер мог опубликовать базу на Apache или IIS, добавьте параметры веб-сервера в ту же секцию web.

# Фрагмент v8project.local.yaml — пример для Apache 2.4
infobases:
  origin:
    connection: "Srvr=srv;Ref=demo"
    web:
      server: apache24               # веб-сервер: iis, apache2, apache22 или apache24
      wsdir: demo                    # имя виртуального каталога
      dir: /var/www/demo             # существующий каталог публикации
      url: https://srv.example/demo  # адрес для открытия базы

server, wsdir и dir нужны команде publish; url — команде launch. Для apache2 и apache22 также нужен conf — путь к файлу конфигурации Apache. Для IIS можно задать os-auth: true — аутентификацию средствами ОС.

v8-runner publish

Инструменты

tools задаёт поиск и запуск внешних утилит. Например, tools.platform настраивает поиск платформы 1С.

Выбор платформы План

Выберите один способ: version — поиск подходящей установленной платформы, path — использование платформы по указанному пути.

# Фрагмент v8project.yaml
workPath: .build
tools:                 # внешние инструменты
  platform:            # платформа 1С
    version: "8.3.27"  # версия для автоматического поиска

Альтернативный вариант — явный путь:

# Альтернативный фрагмент v8project.yaml — пример для Linux
workPath: .build
tools:
  platform:
    path: /opt/1cv8/x86_64/8.3.27.2074  # каталог установленной платформы

Если оба поля отсутствуют, раннер ищет установленную платформу автоматически. Если после объединения основного и локального файлов заданы и path, и version, это ошибка конфигурации. Локальный path не отменяет version из основного файла.

Исполнители операций

providers выбирает, какой инструмент исполнит операцию. Ключ называется именем команды: например, providers.push — исполнитель отправки исходников.

# Фрагмент v8project.yaml
workPath: .build
providers:        # явно выбранные исполнители операций
  push: designer  # отправка через Конфигуратор
  pull: designer  # выгрузка через Конфигуратор

Если ключ не задан, раннер выбирает исполнителя сам. Если задан — использует только указанного исполнителя, без переключения на другого. Для check ветка определяется форматом проекта.

Настройки операций

Отправка исходников

push.partialLoadThreshold задаёт максимальное число изменённых файлов для частичной загрузки через Конфигуратор. По умолчанию — 20; при превышении порога используется полная загрузка.

# Фрагмент v8project.yaml
workPath: .build
push:                       # настройки отправки исходников
  partialLoadThreshold: 20  # до 20 файлов — частичная загрузка

Тесты

tests хранит настройки YAxUnit и Vanessa Automation. Общий таймаут выполнения задаётся в секундах; параметры конкретных инструментов лежат в tests.yaxunit и tests.va.

# Фрагмент v8project.yaml
workPath: .build
tests:                            # настройки тестовых инструментов
  execution_timeout_seconds: 300  # таймаут выполнения, секунды

Локальные переопределения

Общие настройки хранятся в v8project.yaml, настройки этой машины — в v8project.local.yaml рядом с ним. Раннер сначала читает основной файл, затем локальный.

Вложенные карты объединяются по ключам: локальное значение заменяет одноимённое основное, остальные значения сохраняются. Значения других типов, включая списки, заменяются целиком.

Локальный файл может переопределять workPath, providers, tools и tests, а также объявлять infobases. Он не может менять format и source-set: это общие свойства проекта.

Пример: другой порог загрузки План

Секцию push можно задать в обоих файлах. В основном примере порог равен 20. Добавьте в локальный файл:

# Фрагмент v8project.local.yaml
push:
  partialLoadThreshold: 40  # порог для этой машины

На этой машине итоговый порог будет 40. Остальные общие настройки сохранятся.

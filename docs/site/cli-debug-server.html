debug-server

Команды debug-server поднимают и останавливают сервер отладки 1С, к которому подключаются отладчик и отлаживаемый клиент. Для файловой базы раннер запускает свой dbgs; для базы на кластере раннера с --debug отдаёт адрес сервера отладки кластера.

Вывод

debug-server start

v8-runner debug-server start

Для файловой базы запускает dbgs из той установки, из которой запускается тонкий клиент (launch thin): сервер и клиент одной версии. Сервер слушает только 127.0.0.1 и запускается без пароля. Ответ приходит, когда сервер назвал свой адрес и по нему ответил обработчик протокола rdbg: запущенный процесс или открытый порт готовности не подтверждают. Ответ называет адрес url, порт, PID процесса и сеанс session — 32 шестнадцатеричных знака для debug-server stop. Каждый вызов поднимает новый сервер со своим сеансом. Сервер переживает команду. Запись сеанса, файл адреса и журнал сервера лежат в workPath/debug-server/<сеанс>/. Сеансы, чей сервер уже вышел, убирает следующий debug-server start.

Без --port сервер берёт первый свободный порт окна из 32 портов в полосе 10000–19999. Окно выводится из пути workPath; если оно занято целиком, берётся следующее. Полоса не задевает порты сервера 1С по умолчанию (1540–1591), закреплённые порты стенда раннера (20000 и выше) и динамический диапазон.

Для базы на кластере раннера, запущенном cluster start --debug, команда ничего не запускает: сервер отладки поднимает сам агент кластера. Команда дожидается, пока этот сервер ответит по rdbg, и отдаёт его адрес с owner: "cluster". Управляемый кластер есть только на Windows; на Linux и macOS debug-server работает с файловой базой.

v8-runner debug-server start --owner-pid 9312

Передаёт PID процесса отладчика серверу: с концом этого процесса dbgs выходит сам, даже если отладчик упал и не вызвал debug-server stop. Мёртвый или неизвестный PID — отказ до запуска. Без ключа сервер живёт до debug-server stop. К серверу отладки кластера ключ не применяется: ответ предупреждает об этом в warnings.

v8-runner debug-server start --port 12961

Сервер слушает этот порт. Если порт занят другим процессом, команда отказывает до запуска, а слушающий процесс остаётся работать; если порт заняли между проверкой и запуском, отказ тот же. К серверу отладки кластера ключ не применяется: у него порт кластера.

v8-runner debug-server start --dry-run

Показывает, чей сервер будет поднят и из какой установки взят dbgs. Ничего не запускает и не записывает, сеанса не выдаёт. Такое же превью есть у debug-server stop.

debug-server stop

v8-runner debug-server stop 5f0c2a9d4e3b4c1f8a7d6e5c4b3a2f10

Останавливает сервер отладки этого сеанса и ждёт конца его процесса; запись сеанса снимается только после подтверждённого конца. Процесс узнаётся по записи целиком: если сервер уже вышел, а его PID занял другой процесс, раннер его не трогает. Повторный stop того же сеанса безопасен: сеанса больше нет, и команда успешна, ничего не останавливая. Так же отвечает сеанс, запущенный из другой рабочей копии. Сервер отладки кластера stop не останавливает: он живёт с кластером, команда снимает только сеанс.

Перед удалением workPath остановите его серверы: debug-server stop по каждому сеансу.

Без замка рабочей копии

debug-server start и debug-server stop не ждут замка workPath и замка стенда и базу не открывают: отладчик гасит сервер при отсоединении, даже если в это время идёт push. Сеанс, который прямо сейчас запускает другая команда, stop не трогает и отказывает workspace_busy.

Клиент под отладкой

Адрес из ответа передают отладчику и клиенту: launch thin --debug <url> запускает клиент с ключами /DEBUG -http -attach /DEBUGGERURL <url>, и отладчик сам подключает его предметы отладки, зарегистрированные на сервере (112). Обычный порядок работы отладчика:

v8-runner debug-server start --owner-pid 9312
v8-runner launch thin --debug http://127.0.0.1:12961
v8-runner debug-server stop 5f0c2a9d4e3b4c1f8a7d6e5c4b3a2f10

launch --debug

launch --debug <url> передаёт адрес сервера отладки клиенту предприятия: thin, thick, ordinary или mcp. Ответ launch называет его в debug.url. Перед запуском раннер сервер не проверяет: адрес подтвердил debug-server start, а если сервера уже нет, клиент работает без отладки. launch designer --debug и launch web --debug, адрес не вида http://<хост>:<порт> и ключи отладки в --raw-key рядом с --debug — отказ invalid_argument.

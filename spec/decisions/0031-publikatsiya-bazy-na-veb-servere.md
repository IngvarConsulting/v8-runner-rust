# ADR-0031: У цели два адреса, и публикацию на веб-сервере делает раннер

- Статус: `accepted`
- Дата: `2026-09-14`
- Связанные решения: [ADR-0003](0003-podderzhivat-servernye-ib-dlya-vseh-instrumentov.md), [ADR-0017](0017-v8project-yaml-source-set-kak-glavnyy-konfiguratsionnyy-kontrakt.md), [ADR-0018](0018-perenesti-kontrakt-informatsionnoy-bazy-v-infobase.md), [ADR-0025](0025-nevypolnyayuschee-prevyu-zapuska-klienta.md), [ADR-0030](0030-provaydery-po-operatsiyam-s-umolchaniyami-v-kode.md)

## Контекст

ADR-0030 ввёл вид цели и вывел его из `infobase.connection`, отдав `ws=…`
автономному серверу. Это неверно, и ошибка вскрылась при вычитке документации.

**`ws=` не называет ни вид цели, ни канал администрирования.** По Приложению 7
(`/WS <url>`, `wsn`, `wsp`, `wsa`) это строка веб-подключения к информационной базе,
опубликованной на веб-сервере. За публикацией может стоять что угодно: файловая база,
база кластера или автономный сервер, который публикует себя сам. Вывести из схемы URL
то, чем базу администрировать, нельзя — это догадка ровно того сорта, который
запрещает ADR-0029.

**Адресов у базы всегда два, и это общий шаблон, а не частность ibsrv.** По одному
раннер администрирует базу, по другому её открывают клиентом или браузером. У
автономного сервера расхождение видно сразу: администрируем по SSH-шлюзу, работаем по
HTTP. У файловой и кластерной базы оно ровно такое же, просто второй адрес появляется
не всегда — только если базу опубликовали.

**Публиковать раннер сейчас не умеет, а повод есть.** Чтобы проверить веб-клиент на
кластерной или файловой базе, публикацию делают руками. В составе платформы для этого
есть `webinst` (Приложение 4, раздел 4.14), и она принимает обычную строку соединения,
то есть работает и с файловой базой, и с кластерной.

## Решение

**1. У цели два адреса, и они объявляются разными ключами.**

| Цель | Раннер администрирует | Клиент открывает |
| --- | --- | --- |
| файловая | `infobase.connection: File=…` | `infobase.web.url` после публикации |
| кластер | `infobase.connection: Srvr=…;Ref=…` | `infobase.web.url` после публикации |
| автономный сервер | `infobase.standalone` (`gate` или `launch`) | `infobase.web.url` — адрес самого сервера |

**2. `ws=` в `infobase.connection` не принимается.** Он описывает клиентское
подключение и не называет канал администрирования; принять его и угадать вид цели
значило бы решать по форме строки. Валидация отклоняет такую строку и называет, что
ставить вместо неё: путь файловой базы, строку кластера или секцию `infobase.standalone`.

**3. Вид цели выводится из объявления, а не из URL.** `File=` — файловая, `Srvr=…;Ref=…` —
кластер, наличие `infobase.standalone` — автономный сервер. Две такие декларации сразу
— ошибка валидации: цель одна.

**4. Появляется команда `publish`.** Публичная CLI-команда; в MCP не публикуется
(ADR-0005). Грамматика:

```text
v8-runner publish [--dry-run]
v8-runner publish --delete [--dry-run]
```

Параметры берутся из конфига, а не из флагов — публикация должна быть
воспроизводимой из файла, а не из истории терминала:

```yaml
infobase:
  connection: "Srvr=srv:1541;Ref=demo"
  web:
    server: apache24        # apache2 | apache22 | apache24 | iis
    wsdir: demo             # виртуальный каталог
    dir: /var/www/demo      # физический каталог, должен существовать
    conf: /etc/apache2/httpd.conf   # только apache2 и apache22
    os-auth: false          # только iis
    url: http://localhost/demo      # адрес для клиента
```

**5. Провайдер — `webinst`, пятый в закрытом наборе ADR-0030.** Развилки у публикации
нет: другой утилиты для этого платформа не даёт, поэтому ключ `providers.publish`
валидация отклоняет.

**6. Предусловия названы, а не обнаружены на полпути.** Замеренные по Приложению 4,
4.14 ограничения инструмента: нужны права администратора (в Windows — запрос повышения
привилегий); каталог `-dir` должен существовать; `-osauth` применим только к IIS; у
Apache 2.4 `-confpath` необязателен, у 2.0 и 2.2 обязателен, и неверно указанная версия
сервера ломает публикацию; для IIS 7 и старше запрещена публикация в
`%SYSTEMDRIVE%\Inetpub\wwwroot`. Существующий `default.vrd` при публикации замещается
целиком — это разрушающее действие, поэтому `publish` обязан иметь превью, а удаление
идёт отдельным явным `--delete`.

**7. `launch` получает вид `web`.** `v8-runner launch web` открывает
`infobase.web.url` в браузере. Без объявленного адреса — типизированный отказ с
указанием, что адрес появляется после `publish` или задаётся вручную. Клиент по
веб-подключению (`/WS`) остаётся обычным `launch thin` с тем же адресом.

**8. Публикация не входит ни в одну цепочку умолчаний.** Это отдельное намерение
пользователя: `build` и `test` её не выполняют и не чинят.

## Что решение не делает

- Не настраивает веб-сервер: установка Apache или IIS остаётся на пользователе.
- Не публикует автономный сервер: он отдаёт HTTP сам, `publish` для него отклоняется.
- Не проверяет доступность опубликованного адреса: это дело `launch web` и тестов.

## Reintroduction guard

- Root cause: вид цели выводили из формы строки подключения, а строка описывает
  клиентское подключение, а не администрирование.
- Single owner: `config::validate` — отклонение `ws=` в `connection`, взаимная
  исключительность деклараций цели, проверка секции `web`.
- Detection: тесты валидации на `ws=` в `connection`, на две декларации цели сразу, на
  `providers.publish`; тест, что `launch web` без `infobase.web.url` даёт типизированный
  отказ.

## Последствия

1. `infobase.web` — новая публичная секция конфига: типизированная модель, валидация,
   обе JSON-схемы, `config init`, docs — по чеклисту.
2. `publish` и `launch web` — новые публичные команды CLI; MCP surface не меняется.
3. `webinst` добавляется в locator рядом с `1cv8`, `1cv8c`, `ibcmd` и в закрытый набор
   провайдеров ADR-0030.
4. Долг: реализация идёт после шага 1 ADR-0030 (матрица и снятие `builder`), потому что
   опирается на её матрицу и на форму квитанции о провайдере.

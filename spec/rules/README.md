# Правила продукта

Реестр один — этот каталог. Одно правило — один файл, одно обязательство.

Правила не являются полным описанием продукта: отсутствие записи не отменяет
существующих гарантий. Описание системы — в [arc42](../arc42/architecture.md);
оно рассказывает, как устроено, и ничего не обещает. Правило обещает и называет, чем
проверено.

Модель заимствована из проекта [Unica](https://github.com/IngvarConsulting/unica).

## Как устроено правило

Файл открывается блоком полей между строками `---`, дальше идёт текст: заголовок и тело.
Тело говорит о своём предмете и не пересказывает смысл полей — он описан здесь.

| Поле | Значения | Что значит |
| --- | --- | --- |
| `id` | `INV.<ОБЛАСТЬ>.<ИМЯ>` или `CTR.<ОБЛАСТЬ>.<ИМЯ>` | Имя правила. Одно на весь реестр. |
| `check` | адрес `путь::имя_теста` или список таких адресов | Что падает при нарушении. Имя обязательно: адрес файла с сотней тестов не называет проверку. |
| `gap` | ссылка на задачу | Обязательство согласовано, но ещё не выполнено. Стоит вместо `check`, а не рядом с ним. |
| `version` | целое от единицы | Номер формы у правила, закрепляющего форму данных. Растёт, когда меняется сама форма: состав полей, допустимые значения, вид и порядок строк. |
| `artifact` | путь к файлу | Чем форма закреплена: схема, снимок, грамматика. Проза формой не является. |

Больше полей нет. Ни `status`, ни `governs`, ни `decision`, ни `supersedes`: правило либо
действует, либо его нет.

Плоский список пишется двумя видами — потоковым `[a, b]` и блочным:

```yaml
check:
  - tests/cli_build.rs::build_dry_run_plans_every_source_set
  - tests/cli_convert.rs::convert_dry_run_plans_every_source_set
```

Вид на значение не влияет. Блочный есть потому, что адресов бывает до пяти, и в одну
строку это давало за четыреста знаков.

## Область и имя

Правила разложены по области продукта; область повторяет префикс имени.

| Каталог | О чём |
| --- | --- |
| `cli/` | командная строка: ключи, листья, превью, отказы |
| `wire/` | формы ответа на проводе |
| `config/` | `v8project.yaml` и местный слой |
| `use-cases/` | сценарии: что делает команда и в каком порядке |
| `platform/` | адаптеры платформы 1С и EDT |
| `mcp/` | сервер MCP и его поверхность |

Имя файла называет тему строчными латинскими буквами, цифрами и дефисом. Правило ищут по
предмету, пути исходника или имени проверки через `rg`.

## Закреплённая форма

Правило, закрепляющее форму данных, несёт `artifact` и `version`, а в теле — раздел
«Пример» с блоком кода. Пример либо проходит схему из `artifact`, либо является
фрагментом закреплённого документа, если артефакт схемой не является. Непроверяемый
пример врёт с первой же смены формы, поэтому его проверяет гейт.

Артефакты порождаются из кода и руками не правятся. Команду порождения называет проверка,
сверяющая артефакт с кодом, когда находит расхождение, или комментарий в самом артефакте.

## Как менять

**Правило правят на месте.** Предыдущая форма лежит в Git, и преемников реестр не
заводит: история — забота Git, а не каталога.

**Правило заявляет ровно одно утверждение** и называет ровно то, что проверяет. Предмет,
которому проверки не будет, правилом не становится.

**Обязательство без проверки называет задачу.** У него `check: []` и `gap` со ссылкой:
так долг виден и считается, а не исчезает вместе с записью. Гейт не принимает ни правила
без проверок и без `gap`, ни `gap` при заполненном `check`.

**Число — либо обещание, либо замер.** Обещание в теле правила говорит «столько сейчас»,
и назвать его проверку — обязанность правила. Замер объясняет, почему так вышло, и верен
для своего дня: его пишут прошедшим временем и называют, чем он датирован. Новое
числительное не появляется молча — перечень `NORMATIVE_NUMERALS` называет каждое. Верно
ли число, гейт не судит: на это есть проверка. Цифрами записанное число перечень не
видит — отделить обещание от номера версии, кода выхода и пути прозой нельзя.

## Гейт

`tests/arch_rules.rs` — одиннадцать проверок. Он держит форму записи, а не прозу: реестр
прочитан целиком, имя есть и оно одно, область имени совпадает с каталогом, набор полей
закрыт и обещанное одним значением его и несёт, названная проверка существует и является
проверкой, обязательство без проверок называет разрыв, закреплённая форма называет
существующий артефакт, закреплённый пример проходит свою форму, новое числительное
названо, имя файла переживает клонирование на Windows, номер ADR не возвращается.

Содержание правила гейт не судит — это работа разбора.

```sh
cargo test --test arch_rules
```

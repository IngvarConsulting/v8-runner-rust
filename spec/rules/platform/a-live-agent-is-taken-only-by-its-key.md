# Живого агента берут только по его ключу

Ключ живого агента считается из строки подключения базы, версии платформы, пользователя
базы, `workPath`, версии раннера и учётной записи ОС. Команда берёт живого агента, только если
совпали все части ключа. Ключ — это HMAC с солью учётной записи, а соль лежит в файле,
доступном только ей. В открытом виде ключ не хранится, потому что в строке подключения бывает
пароль. Пароль базы в ключ не входит. Учётные данные команда передаёт сторожу с каждым
запросом. Если они не совпали с теми, с которыми открыта сессия, сторож снимает агента, и
команда поднимает нового.

Поскольку `workPath` входит в ключ, у каждой рабочей копии свой агент. Текущий каталог агента,
его `AgentBaseDir`, ключ хоста и запись лежат не в `workPath`, а в каталоге состояния учётной
записи ОС, в подкаталоге с именем по ключу. Поэтому живой агент не мешает удалить рабочую копию.
Каталоги, в которые агент пишет выгрузку, раннер выставляет в его каталоге ссылкой на каталог
своего тома в `workPath`. Так файлы выгрузки ложатся сразу на том рабочей копии и не
копируются между томами. Рабочая копия по-прежнему не получает файлов агента
(`INV.PLATFORM.A-MANAGED-AGENT-RUNS-IN-ITS-OWN-DIRECTORY`). Запись хранит, кроме ключа, путь
базы в каноническом виде: по нему находят живых агентов одной базы из разных рабочих копий.
Команду и агента связывает блокировка рабочего каталога, под которой команда держит агента
(`INV.PLATFORM.AGENT-SESSION-LIVES-WITH-THE-LOCK`).

# Процесс своего агента переживает команду

Если агент Конфигуратора поднял сам раннер, то после работы команда снимает с него только
своё: подключение к базе (`common disconnect-ib`) и сессию SSH. Процесс агента остаётся
жить вне Job раннера. Следующая команда того же ключа
(`INV.PLATFORM.A-LIVE-AGENT-IS-TAKEN-ONLY-BY-ITS-KEY`) берёт его вместо нового запуска и сама
подключается к базе (`common connect-ib`). Между командами агент не держит ни подключения
к базе, ни учётных данных базы.

На Windows живой агент держит свой текущий каталог и `AgentBaseDir` в `workPath`
(`INV.PLATFORM.A-LIVE-AGENT-IS-TAKEN-ONLY-BY-ITS-KEY`), и пока он жив, рабочую копию не удалить.
Перед удалением её останавливают командой `v8-runner agent stop`. Отказ удаления, который
раннер видит сам, называет живого агента и эту команду.

Вход к живому агенту раннер не защищает сверх того, что делает платформа. Агент пускает по
пользователю базы и его паролю, а к базе без пользователей — с пустым логином
([замер](../../../references/1c/confirmed-runtime-measurements.md), раздел об аутентификации
агента; [вход пользователем ИБ](../../../references/1c/designer-agent/README.md)). Нарушитель на
той же машине может так же легко поднять своего агента на этой базе и подключиться к нему, и
раннер ему для этого не нужен. Поэтому защищаться здесь раннеру нет смысла.

Подключённого агента (`tools.designer_agent.attach`) и шлюз автономного сервера раннер не
поднимает, и временем их жизни не управляет.

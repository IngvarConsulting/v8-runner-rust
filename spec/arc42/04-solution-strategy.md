## 4. Стратегия решения

- Два адаптера — командная строка и MCP — над одним слоем сценариев. Сценарии не знают
  транспорта — [5.2](05-building-block-view.md).
- Кто исполняет операцию, решают данные: матрица «операция и вид цели». Исполнители одной
  операции стоят за общим сценарием — [8.4](08-cross-cutting-concepts.md), [6.2](06-runtime-view.md).
- Процессы, SSH и загрузка по HTTP — в `platform` — [5.5](05-building-block-view.md); пробу
  готовности клиентского MCP сценарий делает по HTTP сам.
- Короткий цикл: изменения ищутся по требованию, загрузка частичная, а при сомнении —
  полная — [8.5](08-cross-cutting-concepts.md), [6.3](06-runtime-view.md).
- Работа человека в сохранности: замок `workPath`, публикация с заменой и откатом, вопрос
  к git перед заменой каталога, критическая фаза записей в базу — [8.3](08-cross-cutting-concepts.md), [8.8](08-cross-cutting-concepts.md), [8.7](08-cross-cutting-concepts.md).
- У команды нет срока; предел бывает у шага, который его объявил — [8.7](08-cross-cutting-concepts.md).
- Один конверт ответа у CLI и MCP; формы данных порождаются из типов и сверяются тестами —
  [8.6](08-cross-cutting-concepts.md), [8.12](08-cross-cutting-concepts.md).
- EDT — одноразово или в одной долгой сессии; MCP-сервер держит свою сессию — [8.9](08-cross-cutting-concepts.md).
- Превью показывает план и ничего не запускает — [6.2](06-runtime-view.md).

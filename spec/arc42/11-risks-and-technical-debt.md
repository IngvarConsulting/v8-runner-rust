## 11. Риски и технический долг

Известные пробелы между гарантиями и кодом — правила с полем `gap`, у каждого своя задача:

```sh
rg -l '^gap:' spec/rules/
```

Сверх них:

- Раннер полагается на утилиты платформы и на окружение машины. Их поведение держат замеры
  и живой прогон в доверенном CI, когда у него есть платформа; остальные тесты идут на
  подставных утилитах.
- Слои нарушены рёбрами из `support` и между `config` и `platform` — [5.2](05-building-block-view.md). Изменение в
  `support` может задеть всё.
- Таблица исполнителей в `docs/CAPABILITIES.md` написана руками; сверку с матрицей обещает
  [правило](../rules/use-cases/an-executor-gap-is-named-in-the-docs.md), пока с `gap` (#298).
- Замок `workPath` локальный. После жёсткого падения файл замка остаётся, и следующая
  команда отказывает, пока его не удалят руками.
- Живая EDT-проверка сервера MCP берёт замок `workPath` на рабочем потоке Tokio: захват пишет
  файл владельца со сбросом на диск и на это время занимает поток. Владелец принял риск
  (#290, #291): захват короткий.
- Рабочая область EDT `workPath/edt-workspace` не исключительна при
  `tools.edt_cli.interactive-mode`: общая сессия сервера MCP держит её между вызовами, а
  инструменты через порт и процесс командной строки поднимают на ней свой EDT —
  [6.7](06-runtime-view.md).
- Многошаговые сценарии не атомарны: `push` по нескольким наборам оставляет базу с
  частью наборов, инкрементальная выгрузка пишет прямо в каталог.
- Переименование набора исходников сбрасывает его состояние.
- MCP по HTTP клиента не аутентифицирует. Привязка не к петлевому адресу держится только
  на сети — [`mcp.http`](../../docs/CONFIGURATION.md).
- Ключ хоста чужого агента или шлюза, не объявленный в конфигурации, не сверяется ни с чем:
  раннер принимает любой и только называет отпечаток, так что подмену хоста в сети он не
  видит. Объявленный ключ сверяется —
  [правило](../rules/platform/a-declared-host-key-is-the-only-one-accepted.md).

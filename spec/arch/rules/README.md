# Правила продукта

> **Пилот.** Здесь десять записей в новой форме — образец для разбора по #275.
> Действующий реестр пока `spec/arch/{decisions,invariants,contracts}/`, и именно он
> в силе. Записи отсюда его не заменяют и гейтом не проверяются. После разбора
> реестр переносится сюда целиком, а прежние каталоги и их машинерия удаляются.
> Порядок при этом обязателен: девять из десяти правил названы полями `establishes`
> одиннадцати решений, и эти ссылки снимаются раньше, чем исчезают прежние каталоги, —
> иначе гейт краснеет на полпути.

В `rules/` — атомарные обязательства, согласованные владельцем. Они не являются полным
описанием продукта: отсутствие записи не отменяет существующих гарантий и их
содержательных проверок.

Правила сгруппированы по области продукта:

- `cli/` — командная строка: ключи, листья, превью;
- `wire/` — формы ответа на проводе;
- `config/` — `v8project.yaml` и местный слой.

Каждая запись содержит `id`, саму гарантию и адреса подтверждающих проверок в `check`.
Поле `gap` со ссылкой на issue означает, что согласованная гарантия ещё не выполнена
полностью; если подтверждающих проверок пока нет, указывается `check: []`.

Запись, закрепляющая форму данных, дополнительно несёт `artifact` — порождаемый файл
схемы — и `version`, номер этой формы. Версия растёт, когда меняется состав полей.

Правило ищут по предмету, пути исходника или имени проверки через `rg`. История — в Git;
почему правило таково, рассказывают задача и PR, которыми оно заведено.

# Снятие защиты адресует и установленное расширение, не только набор

**Решение.** Правка свойств безопасности расширения выбирает цель двумя разными
селекторами, и каждый называет свой предмет: `--name` — набор-расширение проекта,
`--installed-name` — платформенное имя расширения, установленного в базе. Совпадения с
набором второму не требуется: расширение, загруженное отдельным `.cfe`, базе известно
только по имени, и это достаточное основание им распорядиться.

Выбор явный. Неизвестное `--name` отвергается и не превращается в поиск по базе:
молчаливый переход от одного предмета к другому — это правка не того расширения.
Умолчание «все настроенные наборы» остаётся ровно там, где селектора нет ни одного.
Селекторы родительской команды не сочетаются с подкомандами: подкоманда адресует состав
базы сама, и второй способ выбрать цель в том же вызове означал бы два разных предмета
в одной команде.

**Почему.** Расширение попадает в базу не только сборкой из исходников: его ставят
готовым `.cfe` — тестовый фреймворк, вендорское, чужое. Снять с такого безопасный режим
было нечем, хотя команда для этого есть и делает ровно то же самое. Требование «заведи
набор-расширение, чтобы тронуть чужое расширение» — требование соврать в конфиге: набора
с исходниками не существует.

**Цена.** У правки свойств теперь два селектора, и разница между ними держится только
тем, что раннер её объясняет: оба принимают строку, и перепутать их в вызове легко.
Отказ по неизвестному `--name` называет, какой селектор нужен другому предмету.

**Не затрагивает.** [`DEC.2026-09-11.BASE-EXTENSIONS-ARE-A-SEPARATE-SUBJECT`](2026-09-11-base-extensions-are-a-separate-subject.md):
предметы остаются разными, и подкоманды по-прежнему адресуют состав базы. Здесь сказано
только, что правка свойств умеет назвать установленное расширение. Не затрагивает и
правила превью: `--dry-run` у этой команды подчиняется общим —
[ничего не запускает](2026-09-11-preview-stops-before-the-provider-is-dispatched.md) и
[не берёт замок](2026-09-11-preview-does-not-take-the-lock.md).

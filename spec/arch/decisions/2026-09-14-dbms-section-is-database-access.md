# `infobase.dbms` — доступ к СУБД, а не к информационной базе

**Решение.** Секция `infobase.dbms` требуется там, где раннер идёт в СУБД
напрямую: создать серверную информационную базу. Для обычной работы с уже
существующей серверной базой она не нужна. Требование полного DBMS-контракта для
любого сценария на серверном подключении снимается там, где оно не обосновано
действием в СУБД.

**Почему.** Строка `Srvr=…;Ref=…` описывает базу для платформы, а `infobase.dbms` —
физическую СУБД под ней. Сборка, выгрузка и экспорт конфигурации в СУБД не ходят;
требовать у них учётные данные СУБД значит просить лишний секрет ради операции,
которая его не использует.

**Цена.** Существующая валидация требует полный контракт шире, чем это решение:
расхождение сверяется с кодом и снимается отдельной работой, а не объявляется
исправленным.

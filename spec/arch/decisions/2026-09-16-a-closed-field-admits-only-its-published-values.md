# Поле с закрытым перечнем принимает только опубликованные значения

**Решение.** `status` принимает `active`, `planned` и `superseded`, `governs` — `product`
и `process`; значение вне перечня реестр отклоняет. Закрытым проверяется то, что закрытым
и опубликовано: перечень `scope` README называет открытым, и реестр его не сверяет.

**Почему.** Гейт читает оба поля точным равенством, поэтому значение вне перечня не
отвергалось, а оказывалось «ни тем ни другим», и всякая проверка, что на него ветвится,
молча переставала применяться. Правило со `status: activ` уходило из-под проверки
«действующее правило ссылается на недействующее решение»: оно оставалось в дереве, а
решение под ним могло быть непринятым. Глазами опечатку не поймать — индекс печатает
значение как есть, и колонка выглядит заполненной, — а grep по `active` её не находит.
Перечень `governs` лежал в `scripts/arch/registry.py` константой, на которую никто не
ссылался: ось была опубликована дважды и не проверена ни разу.

**Цена.** Новое значение любого из двух полей заводится правкой кода и README, а не одной
записью. Цена взята сознательно: обе оси решают, какие проверки к записи применяются, а не
описывают её.

**Не затрагивает.** `scope`: его перечень README называет открытым, дрейф там виден в
индексе и стоит дешевле запрета. `consumers`: README не объявляет его ни открытым, ни
закрытым, и закрыть его — отдельный предмет. `DEC.2026-09-16.A-SYMBOL-AND-ITS-PATH-SPELL-EACH-OTHER`
оставлял обе оси непроверенными; это решение сужает то, что то оставляло открытым, и
предмета прежнего не трогает.

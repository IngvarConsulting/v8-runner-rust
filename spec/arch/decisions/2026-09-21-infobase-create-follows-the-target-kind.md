# Базу создаёт `infobase create`, и делает это по виду цели

**Решение.** Базу создаёт отдельная команда `infobase create`; `init` наружу не выходит.
Файловая база: `ibcmd` создаёт её сразу с конфигурацией из исходников (`--import`).
Кластер: Конфигуратор одной командой `CREATEINFOBASE` регистрирует базу в кластере и
создаёт базу данных в СУБД (`CrSQLDB=Y`; `SUsr`/`SPwd` из `cluster.user`, если в
кластере заведены администраторы); реквизиты СУБД берутся из секции `dbms`; `rac` —
запасной путь, если Конфигуратор регистрацию не осилил. Автономный сервер: отказ рода
подбора `subject` с рецептом — базу создают `ibcmd server config init` и `ibcmd infobase
create --load|--import|--restore` на его машине до запуска сервера. Для формата EDT
команда создаёт ещё и рабочую область. Созданная база сразу записывается в память,
поэтому первый `push` после неё — обычный. Существующая база — отказ на тех же правах,
что у `infobase restore --create`: у файловой цель наблюдается по каталогу до выбора
исполнителя, у серверной — платформой при исполнении; превью различий не обещает (#100
остаётся вопросом). Порядок исполнителей —
`DEC.2026-09-21.DEFAULT-CHAINS-FOLLOW-THE-TARGET-KIND`.

**Почему.** Прежний `init` создавал базу через `ibcmd` при полном доступе к СУБД и
молчал о кластере: `ibcmd` регистрировать базу в кластере не умеет, а к базе под
кластером его инструменты применять нельзя. Одно имя на два действия — проект и база —
не давало ни завести проект без базы, ни создать базу в готовом проекте.

**Цена.** Прежний `init` синонима не получает: вызов старого `init` в проекте с базой
отказывает и называет `infobase create`.

**Заменяет при реализации.**
`DEC.2026-04-22.INIT-ENSURES-A-SERVER-INFOBASE-THROUGH-IBCMD`. Правил у него нет;
поведение 0.11.0 остаётся до реализации.

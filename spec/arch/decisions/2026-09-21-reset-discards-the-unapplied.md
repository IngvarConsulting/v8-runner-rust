# `reset` отбрасывает непринятое

**Решение.** `reset [<ссылка>]` возвращает основную конфигурацию к конфигурации базы
данных — обратный ход `apply`, базу данных он не трогает. У расширения своя пара, откат
идёт с `-Extension`. Своё непринятое — отправленное `push --no-apply`, что видно по
памяти о поколении, — отбрасывается молча; чужое, сделанное в Конфигураторе, — только с
`--force`. Исполнители — Конфигуратор `/RollbackCfg` и `ibcmd config reset`; в наборе
SSH-шлюза отката нет. Слово взято у платформы и совпадает с `git reset --hard`, который
тоже уничтожает незафиксированное; `restore` не взято — оно занято образом `.dt`.

**Почему.** Состояние «есть непринятое» — штатное, ради него разведены `push --no-apply`
и `apply`; ему нужен обратный ход, иначе от отложенных изменений нельзя отказаться иначе
как полной загрузкой поверх.

**Цена.** Различить своё и чужое непринятое можно только памятью о поколении
(`DEC.2026-09-21.THE-GENERATION-GUARDS-EVERY-EXCHANGE`); без памяти всё непринятое —
чужое.

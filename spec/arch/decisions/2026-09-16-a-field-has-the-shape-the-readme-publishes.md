# Поле имеет ту форму, которую публикует README

**Решение.** Поле, объявленное одним значением, списком быть не может; поле, объявленное
перечнем, несёт перечень. Проверяются те поля, у которых форма и есть смысл: остальные
читает `prop_values`, которому скаляр и список равно годятся, и спорить там не о чем.

**Почему.** Форму README публикует наравне со смыслом, а проверки читали её как
известную, и расхождение оборачивалось не отказом, а неверным «принято».
`superseded-by` перечнем называл двух преемников там, где обещан один, и
`DEC.2026-09-16.A-SYMBOL-RESOLVES-TO-A-RECORD` покорно разрешал обоих. `status` перечнем
ронял гейт целиком: принадлежность закрытому перечню проверяется хешированием, и вместо
строки об одной записи реестр не судил ни одной. `id` перечнем ронял его тем же способом
раньше — на построении отображения символов.

**Цена.** Подмножество YAML сужается: где README обещает одно значение, перечень теперь
отказ, даже из одного элемента. Автору это стоит одной правки, читателю проверок — права
считать форму известной, а не угадывать её по значению.

**Не затрагивает.** `check`, `realized`, `establishes` и `supersedes`: их читает
`prop_values`, и один адрес там равен списку из одного. Значения полей: форму реестр
знает, перечень `scope` по-прежнему открыт.

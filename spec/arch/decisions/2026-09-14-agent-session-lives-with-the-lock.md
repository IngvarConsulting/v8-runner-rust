# Сессия агента живёт ровно столько, сколько владение `workPath`

**Решение.** Провайдер `agent` открывает сессию при захвате workspace lock и
закрывает при его освобождении. Вложенная оркестрация идёт в той же сессии: у
сборки загрузка исходников и обновление конфигурации базы — два шага одного
разговора, а не два процесса.

**Почему.** Замок уже владеет рабочим каталогом на время команды, и второй
владелец времени жизни породил бы вопрос, чей срок главнее. Один живой процесс на
команду заодно снимает повторный запуск платформы между шагами.

**Не затрагивает.** Долгоживущий MCP-сервер: там между вызовами живёт сессия EDT,
а агентская по-прежнему открывается под замок конкретной команды.
